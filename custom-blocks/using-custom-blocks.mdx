Once custom blocks are built and deployed, using them in your workflows is just as easy as using pre-built blocks. They appear in your block library and work seamlessly with the visual canvas.

## Accessing Custom Blocks

Custom blocks appear in the block library under the "Custom Blocks" section. This is where you'll find all the blocks from your connected block servers.

  <img src="/images/custom-blocks/block-library-custom.png" alt="Block library showing custom blocks section" />
</Frame>

### Block Library Organization

The custom blocks section shows:

- **Individual blocks** available for use
- **Block servers** that are connected to your workspace
- **Server status** indicating if servers are active and responsive
- **Block descriptions** explaining what each custom block does

## Adding Custom Blocks to Workflows

Use custom blocks exactly like pre-built blocks:

1. **Double-click on the canvas** to open the block library
2. **Navigate to Custom Blocks** section
3. **Select your custom block** from the available options
4. **Configure the block** using the sidebar
5. **Connect to other blocks** as needed

<Frame>
  <img src="/images/custom-blocks/adding-custom-block.png" alt="Adding a custom block to the workflow canvas" />
</Frame>

Custom blocks integrate seamlessly with pre-built blocks, so you can mix and match as needed for your workflows.

## Configuring Custom Blocks

Custom blocks have configuration interfaces just like pre-built blocks, but the options depend on how the block was designed by its developer.

### Input Configuration

Set up inputs for your custom block:

- **Required parameters** that the block needs to function
- **Optional settings** that modify block behavior
- **Data connections** from other blocks in your workflow

### Output Usage

Custom blocks produce outputs that other blocks can use:

- **Structured data** that flows to connected blocks
- **Status information** about the block's execution
- **Error details** if something goes wrong

## Working with Block Servers

### Server Connection

Block servers connect to your workspace using API keys. Once connected, all blocks from that server become available in your block library.

### Server Status

Monitor the status of your block servers:

- **Active**: Server is running and blocks are available
- **Inactive**: Server is not responding or has issues
- **Error**: Server has encountered problems

### Multiple Servers

You can connect multiple block servers to your workspace, each containing different sets of custom blocks. This allows for organized development where different teams or purposes have their own servers.

## Best Practices for Using Custom Blocks

### Understand Block Purpose

Before using a custom block, understand what it does and when it's appropriate to use. Check the block description and any documentation provided by the developer.

### Test Thoroughly

Custom blocks may have different behavior than pre-built blocks, so test your workflows thoroughly when incorporating new custom blocks.

### Monitor Performance

Keep an eye on how custom blocks affect your workflow performance, especially if they perform complex operations.

### Communicate with Developers

If you encounter issues with custom blocks or need modifications, communicate with the development team to improve the blocks.

## Troubleshooting Custom Blocks

### Block Not Appearing

If a custom block doesn't appear in your library:

- Check that the block server is active
- Verify the server is connected to your workspace
- Confirm you have the right permissions

### Configuration Issues

If you can't configure a block properly:

- Review the block documentation
- Check that you're providing the right input types
- Verify any required connections are in place

### Execution Problems

If custom blocks fail during workflow execution:

- Check the error messages for specific issues
- Verify that inputs are in the expected format
- Contact the block developer if errors persist
