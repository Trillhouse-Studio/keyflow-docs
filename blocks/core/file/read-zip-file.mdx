---
title: Read ZIP File
---

### Overview

The Read ZIP File block extracts and reads the contents of ZIP archives, making compressed files accessible for processing in your workflows. This block automatically extracts supported file types and converts their contents to text format, enabling seamless integration with other data processing blocks.

<Tip>Perfect for processing bulk document collections, extracting archived datasets, or analyzing compressed file bundles in a single step.</Tip>

---

### Inputs

<ParamField query="Zip File Reader" type="file" required>
  The ZIP file that you want to extract and read contents from. Only `.zip` files are accepted.
</ParamField>

### Outputs

<ParamField query="file_contents" type="string[]">
  An array containing the actual text contents of each extracted file, converted to UTF-8 format for easy processing.
</ParamField>

<br></br>

<Accordion title="Additional Outputs">
  <ParamField query="file_names" type="string[]">
    An array listing the names and paths of all files found inside the ZIP archive, maintaining the original folder structure.
  </ParamField>
</Accordion>

---

### Best Practices

<Steps>
  <Step title="Use Supported File Types">
    Only include supported file formats in your ZIP archives to ensure successful extraction.
    ```text ⚠️ Bad Example wrap
    Including .exe, .img, or other binary files in ZIP
    ```
    ```text ✅ Good Example wrap
    ZIP containing .csv, .pdf, .json, .txt, .html, or .md files
    ```
  </Step>

  <Step title="Organize File Structure">
    Maintain clear folder structures in your ZIP files for easier identification and processing of extracted contents.
  </Step>

  <Step title="Validate File Sizes">
    Be mindful of large PDF files or extensive text documents within ZIP archives, as they may impact processing time and memory usage.
  </Step>
</Steps>

### Troubleshooting

<AccordionGroup>
  <Accordion title="Why am I getting 'File type not supported' errors?">
    The block only supports specific file types within ZIP archives: `.csv`, `.pdf`, `.html`, `.json`, `.txt`, `.text`, and `.md` files.
    
    <Warning>Binary files, executables, images, and other formats are not supported and will cause the block to fail.</Warning>
    
    Solution: Remove unsupported files from your ZIP archive or create a separate ZIP containing only supported file types.
  </Accordion>

  <Accordion title="The block fails with 'Error occurred while reading zip file' - what's wrong?">
    <Tip>This error usually indicates a corrupted ZIP file or access issues.</Tip>
    
    Common solutions:
    1. Verify the ZIP file is not corrupted by opening it manually
    2. Ensure the file was uploaded correctly to Keyflow
    3. Check that the ZIP file isn't password-protected
    4. Confirm the file extension is exactly `.zip` (case-sensitive)
  </Accordion>

  <Accordion title="Why are some files missing from the output arrays?">
    The block automatically filters out:
    - Hidden files (those starting with `.`)
    - Directories/folders (only files are processed)
    - Unsupported file types
    
    <Info>Both output arrays (`file_names` and `file_contents`) will have the same length and correspond to each other by index position.</Info>
    
    If you expected more files, check that they meet the supported file type criteria and aren't hidden files.
  </Accordion>

  <Accordion title="How do I handle large ZIP files or many files?">
    For ZIP archives containing many files or large documents:
    - Consider breaking large ZIP files into smaller archives
    - Use the `file_names` output to identify specific files before processing
    - Implement downstream filtering to process only needed files
    
    <Warning>Processing very large ZIP files may consume significant compute resources and time.</Warning>
  </Accordion>

  <Accordion title="Can I read password-protected ZIP files?">
    No, the Read ZIP File block does not support password-protected or encrypted ZIP archives. You'll need to extract and re-compress the files without password protection before using this block.
  </Accordion>
</AccordionGroup>
