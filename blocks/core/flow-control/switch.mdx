---
title: Switch
---

### Overview

Routes workflow execution to different paths based on matching a value against predefined cases. This block compares an input value against a list of cases and directs data to the matching output path.

<Tip>Perfect for multi-way branching logic when you need to route data based on specific values rather than complex conditions.</Tip>

---

### Inputs

<ParamField query="Value" type="Any" required>
  The data that will be passed through to the matching output path.
</ParamField>

<ParamField query="Criterion" type="Text" required>
  The value to match against your defined cases. This determines which output path will be activated.
</ParamField>

<ParamField query="Cases" type="List">
  Define the cases to match against. Each case creates a corresponding output path.
</ParamField>

### Outputs

The outputs are dynamically generated based on your defined cases, plus a default path for unmatched values.

<ParamField query="Default" type="Any">
  Receives the input value when no cases match the criterion.
</ParamField>

<br></br>

<Accordion title="Additional Outputs">
  <ParamField query="Dynamic Case Outputs" type="Any">
    One output is created for each case you define. The matching case output receives the input value.
  </ParamField>
</Accordion>

### Best Practices

<Steps>
  <Step title="Use Descriptive Case Names">
    Choose clear case names that indicate what they represent for easier workflow understanding.
    ```text ⚠️ Bad Example wrap
    Cases: ["A", "B", "C"]
    ```
    ```text ✅ Good Example wrap
    Cases: ["high_priority", "medium_priority", "low_priority"]
    ```
  </Step>

  <Step title="Plan for the Default Case">
    Always connect the Default output to handle values that don't match any defined cases.
    ```text ✅ Good Example wrap
    Cases: ["approved", "pending", "rejected"]
    Default: Handle unexpected status values
    ```
  </Step>

  <Step title="Keep Cases Simple and Exact">
    Use exact text matches. For complex matching logic, consider using the If-Else block instead.
  </Step>
</Steps>

### Troubleshooting

<AccordionGroup>
  <Accordion title="Why does my data always go to Default?">
    The criterion value doesn't exactly match any of your defined cases. Check for exact spelling, capitalization, and spacing.
    
    ```text Example Solution wrap
    Criterion: "High Priority"
    Cases: ["high priority"] ← Won't match due to capitalization
    
    Fix: Make cases match exactly: ["High Priority"]
    ```
  </Accordion>

  <Accordion title="How do I add or remove cases?">
    <Tip>Use the Cases configuration panel</Tip>
    In the Cases field, you can add new case objects or remove existing ones. Each case automatically creates a corresponding output handle.
    
    <Info>Output handles update automatically when you modify cases</Info>
  </Accordion>

  <Accordion title="Can I match numbers or other data types?">
    The Switch block compares the criterion as text. For numeric or complex comparisons, use the If-Else block instead.
    
    ```text When to use Switch vs If-Else wrap
    Switch: Exact text matching ("status", "category", "type")
    If-Else: Complex conditions (number > 10, contains text, etc.)
    ```
    
    <Warning>Numeric values are converted to strings for comparison</Warning>
  </Accordion>
</AccordionGroup>
