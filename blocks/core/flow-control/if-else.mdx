title: If Else
---

### Overview

Evaluates conditions and directs workflow execution based on whether the conditions are met. This block supports complex conditional logic with multiple conditions, logical operators, and custom output paths.

<Tip>Essential for creating branching logic, data validation, and conditional processing in your workflows.</Tip>

---

### Inputs

<ParamField query="Conditions" type="Complex" required>
  Define conditional blocks with IF, ELSE IF, and ELSE statements. Each block can contain multiple conditions combined with AND/OR operators.
</ParamField>

### Outputs

The outputs are dynamically generated based on your conditional blocks. Each condition block creates its own output path, plus a default "else" path.

<ParamField query="Dynamic Outputs" type="Any">
  Output paths are created for each named condition block (e.g., "if", "else", custom names). The workflow will follow the path of the first condition that evaluates to true.
</ParamField>

### Best Practices

<Steps>
  <Step title="Use Descriptive Condition Names">
    Give your condition blocks meaningful names that describe what they're checking.
    ```text ⚠️ Bad Example wrap
    Condition blocks: "Case 1", "Case 2", "Case 3"
    ```
    ```text ✅ Good Example wrap
    Condition blocks: "high_priority", "medium_priority", "low_priority"
    ```
  </Step>

  <Step title="Order Conditions by Priority">
    Place the most important or most likely conditions first, as the block stops at the first match.
    ```text ✅ Good Example wrap
    1. IF: urgent_flag is true
    2. ELSE IF: priority > 5
    3. ELSE: default_processing
    ```
  </Step>

  <Step title="Combine Conditions Logically">
    Use AND for conditions that must all be true, OR for conditions where any can be true.
  </Step>
</Steps>

### Troubleshooting

<AccordionGroup>
  <Accordion title="Why is my condition not working correctly?">
    Check that your condition type matches your data type and that comparison values are formatted correctly.
    
    ```text Example Solution wrap
    For numbers: Use "[Number] is greater than" with numeric comparison value "10"
    For text: Use "[Text] contains" with text comparison value "error"
    For booleans: Use "[Boolean] is true" (no comparison value needed)
    ```
  </Accordion>

  <Accordion title="How do I create complex conditions with AND/OR?">
    <Tip>Add multiple conditions within a single block and specify operators</Tip>
    Example: Check if (score > 80 AND status = "active") OR (priority = "high")
    
    Conditions:
    1. score > 80 (AND)
    2. status = "active" (OR) 
    3. priority = "high"
    
    <Info>The block processes conditions left to right with the operators you specify</Info>
  </Accordion>

  <Accordion title="What condition types are available?">
    **Number conditions:** greater than, less than, equal to
    **Text conditions:** exact match, contains, starts with, ends with, is in, is not in
    **Boolean conditions:** is true, is false
    **General conditions:** is empty, is not empty
    
    <Warning>Make sure your data type matches the condition type you choose</Warning>
  </Accordion>

  <Accordion title="Why does my workflow always go to 'else'?">
    This happens when none of your conditions evaluate to true. Common causes:
    1. Data type mismatch (text vs number)
    2. Incorrect comparison values
    3. Missing or null input data
    4. Case-sensitive text comparisons
    
    <Info>Add logging before the If-Else block to verify your input data</Info>
  </Accordion>
</AccordionGroup>
