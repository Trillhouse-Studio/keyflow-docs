title: AI Switch
---

### Overview

Uses artificial intelligence to intelligently route data to different paths based on natural language conditions. Unlike traditional switch statements that require exact matches, this block evaluates data using AI reasoning to determine the best matching condition.

<Tip>Perfect for complex decision-making where traditional exact-match logic isn't sufficient, like content categorization or sentiment-based routing.</Tip>

---

### Inputs

<ParamField query="Data" type="Any" required>
  The data to be evaluated and routed to the appropriate output path.
</ParamField>

<ParamField query="Multiple Matches" type="Toggle">
  When enabled, allows the AI to select multiple matching conditions instead of just the best match.
</ParamField>

<ParamField query="Cases" type="List" required>
  Define the conditions using natural language descriptions. Each case has a name and a condition description.
</ParamField>

<br></br>

<Accordion title="Advanced Settings">
  <ParamField query="Model" type="Select">
    Choose the AI model to use for decision-making. Different models may provide varying levels of accuracy and speed.
  </ParamField>
</Accordion>

### Outputs

The outputs are dynamically generated based on your defined cases, plus a default path for unmatched data.

<ParamField query="default" type="Any">
  Receives the input data when no conditions are met or if the AI cannot make a confident decision.
</ParamField>

<br></br>

<Accordion title="Additional Outputs">
  <ParamField query="Dynamic Case Outputs" type="Any">
    One output is created for each case you define. The AI determines which output(s) receive the data based on condition matching.
  </ParamField>

  <ParamField query="model" type="Text">
    The AI model that was used for the decision.
  </ParamField>

  <ParamField query="cost" type="Number">
    The cost of the AI inference in USD.
  </ParamField>

  <ParamField query="in_tokens" type="Number">
    Number of input tokens consumed by the AI model.
  </ParamField>

  <ParamField query="out_tokens" type="Number">
    Number of output tokens generated by the AI model.
  </ParamField>
</Accordion>

### Best Practices

<Steps>
  <Step title="Write Clear, Descriptive Conditions">
    Use natural language that clearly describes when data should match each case.
    ```text ⚠️ Bad Example wrap
    Case: "positive"
    Condition: "good"
    ```
    ```text ✅ Good Example wrap
    Case: "positive_feedback"
    Condition: "Customer feedback expressing satisfaction, happiness, or praise"
    ```
  </Step>

  <Step title="Use Specific and Distinct Conditions">
    Make sure conditions are different enough that the AI can distinguish between them clearly.
    ```text ✅ Good Example wrap
    Case 1: "urgent_support" - "Customer reports system is down or critical functionality broken"
    Case 2: "general_inquiry" - "Customer asking questions about features or how to use the product"
    Case 3: "billing_issue" - "Customer has questions or problems related to payments or invoices"
    ```
  </Step>

  <Step title="Test with Sample Data">
    Always test your conditions with representative data to ensure the AI makes correct routing decisions.
  </Step>
</Steps>

### Troubleshooting

<AccordionGroup>
  <Accordion title="Why does my data always go to 'default'?">
    This can happen when conditions are too vague, conflicting, or when the AI cannot confidently match the data to any condition.
    
    ```text Example Solution wrap
    Instead of: "positive data"
    Use: "Customer reviews with 4-5 star ratings or containing words like 'excellent', 'great', 'love it'"
    ```
  </Accordion>

  <Accordion title="How does Multiple Matches work?">
    <Tip>Enable Multiple Matches for overlapping categories</Tip>
    When enabled, the AI can route data to multiple outputs if it matches several conditions simultaneously.
    
    Example: A customer message about "billing problems causing system downtime" might match both "billing_issue" and "technical_support" cases.
    
    <Info>With Multiple Matches disabled, the AI selects only the best single match</Info>
  </Accordion>

  <Accordion title="How can I improve AI accuracy?">
    **Make conditions specific:** Include examples of what should and shouldn't match
    **Add context:** Explain the business logic behind each condition
    **Use consistent language:** Keep condition descriptions in a similar style
    **Test iteratively:** Refine conditions based on actual results
    
    <Warning>Very complex conditions may confuse the AI - consider breaking them into simpler, more focused cases</Warning>
  </Accordion>

  <Accordion title="What should I consider about AI costs?">
    AI Switch blocks consume tokens and incur costs for each decision. Consider:
    - Using more efficient models for simple decisions
    - Caching results when processing similar data repeatedly
    - Using traditional Switch blocks for exact-match scenarios
    
    <Info>Monitor the cost and token outputs to track your usage</Info>
  </Accordion>
</AccordionGroup>
