---
title: Write JSON
---

### Overview

Adds or modifies data within a JSON object by specifying key paths and values. This block supports both simple key-value operations and nested object manipulation using dot notation.

<Tip>Perfect for building configuration objects, updating API payloads, or creating structured data from individual values.</Tip>

---

### Inputs

<ParamField query="JSON" type="Object">
  The original JSON object to modify. If not provided, a new empty object will be created.
</ParamField>

<ParamField query="Values" type="Text" required>
  The values to write to the JSON object. For multiple values, use comma-separated format.
</ParamField>

<ParamField query="Key" type="Text" required>
  The key path where to write the value. Supports dot notation for nested objects (e.g., `user.profile.name`). For multiple keys, use comma-separated format.
</ParamField>

### Outputs

<ParamField query="updated_json" type="Object">
  The modified JSON object with the new or updated key-value pairs.
</ParamField>

---

### Best Practices

<Steps>
  <Step title="Match Keys with Values">
    Ensure the number of keys matches the number of values when using comma-separated lists.
    ```text ⚠️ Bad Example wrap
    Key: "name, email, age"
    Values: "John, john@example.com"  // Missing age value
    ```
    ```text ✅ Good Example wrap
    Key: "name, email, age"
    Values: "John, john@example.com, 25"  // All values provided
    ```
  </Step>

  <Step title="Use Dot Notation for Nested Objects">
    Create nested structures efficiently with dot notation instead of multiple Write JSON blocks.
    ```text ✅ Good Example wrap
    Key: "user.profile.name, user.settings.theme"
    Values: "John Smith, dark"
    ```
  </Step>

  <Step title="Handle Missing Input Gracefully">
    The block creates a new empty object if no JSON input is provided, making it perfect for building objects from scratch.
  </Step>
</Steps>

### Troubleshooting

<AccordionGroup>
  <Accordion title="Why is my nested object not being created?">
    Check that you're using proper dot notation and that your key path is correctly formatted.
    
    ```json Example Solution wrap
    // To create: {"user": {"profile": {"name": "John"}}}
    // Use Key: "user.profile.name"
    // Use Values: "John"
    ```
  </Accordion>

  <Accordion title="What happens if I have more keys than values?">
    <Warning>Extra keys will receive undefined values</Warning>
    Always ensure your comma-separated keys and values lists have the same number of items.
    
    ```text Good Practice wrap
    Key: "name, email"
    Values: "John, john@example.com"
    // Both have 2 items ✅
    ```
  </Accordion>

  <Accordion title="Can I overwrite existing values?">
    Yes! The block will update existing keys with new values while preserving other properties.
    
    ```json Example wrap
    // Original: {"name": "Old Name", "email": "test@example.com"}
    // Key: "name", Values: "New Name"
    // Result: {"name": "New Name", "email": "test@example.com"}
    ```
    
    <Info>Existing nested objects are preserved when updating specific nested properties</Info>
  </Accordion>
</AccordionGroup>
