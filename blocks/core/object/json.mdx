title: JSON
---

### Overview

Creates and manipulates JSON objects, enabling structured data handling and transformation. The JSON block provides flexible methods for building JSON objects from static values, dynamic inputs, or a combination of both.

<Tip>Perfect for building API request bodies, configuration objects, or structured data for other blocks that require JSON input.</Tip>

---

### Inputs

<ParamField query="data" type="Object" required>
  A list of key-value pairs that define the properties of the resulting JSON object. Each property can be configured with:
  - **Key**: The property name in the JSON object
  - **Value**: The property value (can be static text or left empty for dynamic input)
  - **Type**: Data type conversion (string, number, boolean, object)
</ParamField>

<br></br>

### Outputs

<ParamField query="json" type="Object">
  The generated JSON object containing all configured properties with their values properly typed and formatted.
</ParamField>

---

### Best Practices

<Steps>
  <Step title="Choose Appropriate Data Types">
    Always specify the correct data type for each property to ensure proper JSON formatting and prevent type-related errors in downstream blocks.
  </Step>
  
  <Step title="Use Meaningful Property Names">
    Choose descriptive property names that clearly indicate the data they contain, especially when creating dynamic input handles.
  </Step>
  
  <Step title="Validate Complex Objects">
    When using object type properties, ensure the input JSON strings are properly formatted to avoid parsing errors.
  </Step>
  
  <Step title="Plan for Scalability">
    Use the hybrid approach when you need a mix of static and dynamic properties, allowing for flexible data structures that can adapt to different scenarios.
  </Step>
</Steps>

### Troubleshooting

<AccordionGroup>
  <Accordion title="Why is my number showing as a string in the output?">
    Ensure you've selected "number" as the data type for numeric properties. If the type is set to "string", all values will be treated as text.
    
    <Warning>Check that your input values are valid numbers when using the number type</Warning>
  </Accordion>
  
  <Accordion title="How do I create nested JSON objects?">
    For nested objects, use the "object" data type and provide a valid JSON string as the value:
    ```json
    {"key": "value", "nested": {"innerKey": "innerValue"}}
    ```
    
    <Tip>You can also connect the output of another JSON block to create nested structures</Tip>
  </Accordion>
  
  <Accordion title="What happens if I don't connect a dynamic input?">
    Properties with unconnected dynamic inputs will have `null` values in the output JSON object.
    
    <Info>This behavior allows for optional properties that may not always have values</Info>
  </Accordion>
  
  <Accordion title="Can I modify existing JSON objects?">
    The JSON block creates new objects rather than modifying existing ones. To modify JSON objects, consider using the Write JSON block instead.
    
    <Note>For simple property additions, you can use the hybrid approach with the existing object as a base</Note>
  </Accordion>
  
  <Accordion title="How do I handle boolean values correctly?">
    For boolean properties:
    - Use the "boolean" data type
    - Input "true" or "false" as text values
    - The block will convert these to proper JSON boolean values
    
    ```json
    Correct: {"isActive": true}
    Incorrect: {"isActive": "true"}
    ```
  </Accordion>
</AccordionGroup>
