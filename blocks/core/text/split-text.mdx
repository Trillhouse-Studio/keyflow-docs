---
title: Split Text
---

### Overview

Divides text into separate parts using specified delimiters, converting strings into manageable arrays. Perfect for processing comma-separated lists, splitting paragraphs, or extracting individual elements from formatted text.

<Tip>Automatically trims whitespace from each split item, giving you clean, ready-to-use text segments.</Tip>

---

### Inputs

<ParamField query="String" type="string" required>
  The text you want to split into an array of separate strings.
</ParamField>

<ParamField query="Split Characters" type="string" default="space">
  Characters that define where the text should be divided. Common examples include commas, semicolons, or pipes.
</ParamField>

<br></br>

<Accordion title="Advanced Settings">
  <ParamField query="Newline Split" type="boolean" default="false">
    When enabled, splits the text on newline characters (`\n`) instead of the specified split characters. Useful for processing multi-line text or lists.
  </ParamField>
</Accordion>

### Outputs

<ParamField query="String Array" type="string[]">
  An array containing each segment of the original text as separate strings, with whitespace automatically trimmed from each item.
</ParamField>

---

### Best Practices

<Steps>
  <Step title="Choose Appropriate Delimiters">
    Select split characters that actually exist in your text and won't create unexpected results.
    ```text ⚠️ Bad Example wrap
    Text: "apple,banana,cherry"
    Split Characters: ";"
    Result: ["apple,banana,cherry"] (no splitting occurs)
    ```
    ```text ✅ Good Example wrap
    Text: "apple,banana,cherry"
    Split Characters: ","
    Result: ["apple", "banana", "cherry"]
    ```
  </Step>

  <Step title="Use Newline Split for Multi-line Text">
    When processing paragraphs or line-based data, enable the newline split option for better results.
  </Step>

  <Step title="Handle Empty Results">
    Consider what happens when your input string is empty or doesn't contain the split characters - you'll get an empty array or single-item array respectively.
  </Step>
</Steps>

---

### Troubleshooting

<AccordionGroup>
  <Accordion title="Why is my text not being split?">
    The split characters you specified don't exist in your input text, or the newline split option doesn't match your text format.
    
    ```json Example Solution wrap
    {
      "input": "apple|banana|cherry",
      "split_characters": "|",
      "result": ["apple", "banana", "cherry"]
    }
    ```
  </Accordion>

  <Accordion title="Getting unexpected extra spaces in results?">
    <Tip>The block automatically trims whitespace, but embedded spaces within words are preserved</Tip>
    This usually happens when your split characters include spaces or when there are multiple consecutive delimiters. The block trims leading and trailing whitespace from each segment automatically.
  </Accordion>

  <Accordion title="Newline split not working as expected?">
    Ensure your text actually contains newline characters (`\n`). Text from some sources may use different line break formats.
    
    <Info>When newline split is enabled, all other split characters are ignored</Info>
  </Accordion>

  <Accordion title="Getting an empty array as output?">
    This happens when your input string is empty, null, or undefined. Verify that your input connection is providing valid text data.
    
    <Warning>Empty or null input strings always return an empty array, regardless of split settings</Warning>
  </Accordion>
</AccordionGroup>
