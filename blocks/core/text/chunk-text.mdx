---
title: Chunk Text
---

### Overview

Breaks down large text into smaller, fixed-size pieces based on character count. Essential for processing lengthy content that needs to be divided into manageable segments for analysis, API requests, or downstream processing.

<Tip>Automatically handles remainder text, ensuring no content is lost during the chunking process.</Tip>

---

### Inputs

<ParamField query="Text" type="string" required>
  The text content you want to break up into smaller chunks.
</ParamField>

<ParamField query="Chunk Size" type="number" required>
  The maximum number of characters each chunk should contain. Must be a positive integer.
</ParamField>

### Outputs

<ParamField query="Text Chunks" type="string[]">
  An array of text segments, each containing up to the specified number of characters. The final chunk may be shorter if the remaining text is less than the chunk size.
</ParamField>

---

### Best Practices

<Steps>
  <Step title="Choose Optimal Chunk Sizes">
    Select chunk sizes that balance processing efficiency with content coherence.
    ```text ⚠️ Bad Example wrap
    Text: "The quick brown fox jumps over the lazy dog"
    Chunk Size: 5
    Result: ["The q", "uick ", "brown", " fox ", "jumps", " over", " the ", "lazy ", "dog"]
    (Words are broken mid-character)
    ```
    ```text ✅ Good Example wrap
    Text: "The quick brown fox jumps over the lazy dog"
    Chunk Size: 20
    Result: ["The quick brown fox ", "jumps over the lazy ", "dog"]
    (More readable chunks that preserve word boundaries better)
    ```
  </Step>

  <Step title="Consider Downstream Processing">
    Match your chunk size to the requirements of subsequent blocks or API limitations in your workflow.
  </Step>

  <Step title="Account for Content Type">
    Use smaller chunks for detailed analysis tasks and larger chunks for general processing or when preserving context is important.
  </Step>
</Steps>

### Troubleshooting

<AccordionGroup>
  <Accordion title="Why am I getting an error about invalid chunk size?">
    The chunk size must be a positive integer (whole number greater than zero).
    
    ```json Example Solution wrap
    {
      "text": "Sample text content",
      "chunk_size": 100,
      "valid": true
    }
    ```
    <Warning>Decimal numbers, zero, negative numbers, and non-numeric values will cause errors</Warning>
  </Accordion>

  <Accordion title="What happens if my text is shorter than the chunk size?">
    <Tip>Short text is returned as a single chunk in the array</Tip>
    When the input text has fewer characters than the specified chunk size, the entire text becomes the first (and only) element in the output array.
  </Accordion>

  <Accordion title="Why is my last chunk shorter than the others?">
    The final chunk contains any remaining characters when the text length isn't evenly divisible by the chunk size.
    
    <Info>This behavior ensures no text content is lost during the chunking process</Info>
  </Accordion>

  <Accordion title="Getting an error about invalid text input?">
    The text input cannot be empty, null, or undefined. Ensure your text input is connected and provides valid string content.
    
    ```json Example Solution wrap
    {
      "text": "At least some text content is required",
      "chunk_size": 50
    }
    ```
  </Accordion>
</AccordionGroup>
