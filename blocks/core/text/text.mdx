### Overview

Create text with dynamic content. Type `@` to select outputs of all connected blocks.

<Tip>Perfect for creating personalized messages, structured prompts, or standardized text formats with dynamic content.</Tip>

---

### Inputs

<ParamField query="Format" type="Text" required>
  Write the text in the format you want to output. Pull in dynamic content using the `@` symbol.
</ParamField>

<br></br>


### Outputs

<ParamField query="Text" type="Text">
  The final formatted text with all placeholders replaced by their corresponding input values.
</ParamField>

### Troubleshooting

<AccordionGroup>
  <Accordion title="Why aren't my placeholders creating input handles?">
    Make sure your placeholders are properly formatted with curly braces around variable names with no spaces.
    
    ```text Example Solution wrap
    Incorrect: { name } or {name }
    Correct: {name}
    ```
  </Accordion>

  <Accordion title="What happens if I don't connect an input?">
    <Tip>Unconnected inputs will use your default value or remain empty</Tip>
    1. If you've set a default value, it will be used for missing inputs
    2. If no default value is set, empty placeholders will be replaced with empty strings
    3. Consider setting meaningful default values for optional content
    <Warning>Empty inputs may result in awkward spacing in your final text</Warning>
  </Accordion>

  <Accordion title="How do I create multiple input handles?">
    Simply add more placeholders in your format string, and input handles will be automatically created.
    
    <Info>Example: "Dear {first_name} {last_name}, your {product} order #{order_id} has been {status}." creates 5 input handles</Info>
  </Accordion>

  <Accordion title="Can I reuse the same placeholder multiple times?">
    Yes! If you use the same placeholder name multiple times in your format, all instances will be replaced with the same input value.
    
    <Info>This is useful for templates where you need to repeat information like names or dates throughout the text</Info>
  </Accordion>
</AccordionGroup>
